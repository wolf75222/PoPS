# T4 native solve-result publication seam

Checkout: `PoPS-numerical-bodies`, branch `codex/api040-numerical-bodies`, base after merge `7d30c03`. Scope is the real `System`/`ProgramContext` solve-result boundary; this is not an implementation of the full C33–C36 host protocol or of asynchronous device completion.

## Reproduced source defect (IMPL, C33/E-OUTCOME)

`System::rollback_step_transaction` previously passed the collective operation/depth check while a successful `SolveOutcome` remained open. `AcceptedSnapshot::restore` then began replacing block state, auxiliary registry and Program accepted state before `ExactNamedField::restore_accepted_state` rejected its still-active field candidate. Thus an unconsumed field solve could yield a partially restored parent. `begin_nested_step_transaction` already rejected an active field when constructing its snapshot, but local-source and prepared-linear outcomes had no enclosing `System` result accounting. `commit_step_transaction` and `finalize_step_transaction` could also advance the parent while such a result remained unresolved.

The patch attaches field, prepared implicit-source and Program prepared-linear outcomes to a shared native authority with an incarnation, attempt ordinal and open-result count. Every external step transition checks this count in its existing collective preflight, before any accepted-state mutation. `step`, `step_cfl` and Program-region entry likewise refuse a pre-existing result. A result left open by a Program body makes the internal step fail; before its accepted snapshot is restored, the result is revoked and the field candidate is rejected. Successful transitions advance the attempt ordinal. A wrong consumption action or recoverable accept-validation failure retains the open result, so the caller can repair and retry `consume()`; the enclosing transaction remains blocked until it does. This leaves the solver's own `SolveStatus`/`SolveAction` untouched. Only `consume(kAccept)` publishes a solved candidate.

The authority does not own `System`. A moved `System` updates its authority's owner address so existing exact-field callbacks reach the transferred `Impl`; destruction or move replacement revokes the old incarnation. A retained outcome then closes with a logic error before dereferencing its raw publication hook or lane. The outcome holds the System execution lane long enough for that revocation vote to be collective. Prepared Krylov workspaces and affine problems expose weak lifetime tokens; while both still live, a stale Program result releases their real reservation, so another solve can reuse them. A peer whose owner remains live releases its candidate before the collective error. Double consumption still fails.

## Witnesses and current verification

`tests/cpp/unit/runtime/test_program_context_contract.cpp` now exercises an actual Poisson field result left open across attempted rollback, commit and nested begin; it verifies scope and state remain intact, consumes the result, then rolls back. The existing prepared Krylov workspace test now attempts rollback while its genuine result is open. Another test retains a genuine field outcome across `System` move, owner destruction and replacement and checks exact revocation/double consumption. Independent tests in `solve_outcome_attempt_review.inc` cover `step`/`step_cfl`/region entry, a real result escaping a Program body before internal rollback, and reuse of a surviving prepared Krylov workspace after its Program System dies. These are native result handles and native buffers, not a host dictionary or injected `checks=True` values.

`c++ -fsyntax-only` passed for `system.cpp`, `system_fields.cpp`, `system_program.cpp` and the C++ test with the worktree's installed Kokkos headers and native dimension 2. `git diff --check` passed. No native test binary was rebuilt or executed in this isolated checkout; the parent owns the integrated build and MPI qualification.

## Limits (SCOPE)

This records **System-owned** attempt publication. It does not make a bare `solve_prepared_affine_outcome` result safe if its caller destroys an independent `KrylovWorkspace` before consuming it; that API's raw workspace lifetime contract is separate. It cannot pin a caller-owned `MultiFab` destination passed to a local source or prepared linear solve; those field objects must outlive their result. It also does not claim concurrency safety for moving/destroying `System` on one thread while another thread executes its result callback, nor does it model GPU cancellation/completion or AMR's independent hierarchy context. The registered open count prevents native step transitions from overtaking a result, but it is not a read/write-set validator for multiple roots or a version counter for every direct mutable field reference.

The result type has not changed serialized checkpoint payloads. The new incarnation and attempt numbers are process-local execution authority. Native restart begin/commit/rollback inherit the step-transition guards. Commit refuses open results, and field/source/prepared-linear solves cannot begin after commit; therefore `finalize_restart_transaction` remains a non-throwing release after external checkpoint effects publish. A Python restart may reuse the same `System`, so it need not create a fresh authority. Individual checkpoint payload restoration methods were not turned into general per-field version checks by this patch. No physics or numerical acceptance criterion changed.
