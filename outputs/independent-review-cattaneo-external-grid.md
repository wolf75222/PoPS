# Independent source review: Cattaneo and path external grids

Reviewed MAIN commit `74a103f` against the authored fixtures and the public run/controller code. No native compile, JIT execution, or environment change was performed.

`ExternalTimeGrid(grid_id)` requires the runtime-control mapping to contain **exactly** `grid_id`. `pops.run(instance, **controls)` forwards controls through `RuntimeInstance._run` and `prepare_program_run` to that strict validation; there is no `time_grid` alias. The Cattaneo program authors `ExternalTimeGrid("steps")`, and the path protocol test authors `ExternalTimeGrid("path_samples")`. Before `74a103f`, their `time_grid=` calls would therefore fail at run preparation. The commit changes only the three call sites to `steps=grid` and `path_samples=(0., dt)`, respectively. It does not change the schemes, state bodies, guards, acceptance criteria, or expected outcomes. Other fixtures whose declared identifier is literally `"time_grid"` correctly retain that keyword.

For each Cattaneo `dt` in `(0.004, 0.002, 0.001)`, `steps = round(0.04 / dt)` is `(10, 20, 40)`. `np.linspace(0., 0.04, steps + 1)` is converted to a tuple of Python floats; it contains respectively 11, 21, and 41 finite, strictly increasing times, including the current time 0 and requested end 0.04. The `max_steps=steps` limit permits exactly the scheduled attempts. Small binary rounding differences between individual intervals and the nominal `dt` are beneath the script's independent scheme comparison tolerance and do not alter the declared physical grid. In the path test, `(0., dt)` supplies one positive interval and matches `t_end=dt` for both accepted and rejected cases. The `ExternalTimeGridController` checks the current and next grid point and refuses an absent endpoint.

Cattaneo calls no `program.store_history` and no `history_global`: its post-run `gather()` reads both published states through `state_global`, reshapes them and saves the actual arrays before comparing with its oracle. Thus the M06 post-rotation slot issue is inapplicable here. The path fixture also has no history reads. I found no second source defect in these two gridding/readback paths that would justify another change before JIT.

Evidence inspected: `python/pops/time/_step/strategy.py` (`ExternalTimeGrid.validate_runtime_controls`), `python/pops/_api.py` (`run`), `python/pops/runtime/_runtime_instance.py` (`_run`), `python/pops/runtime/_step_strategy.py` (`prepare_program_run`, `ExternalTimeGridController`), the two changed fixtures, and the Cattaneo oracle. This verdict is source-only; installed native behavior awaits the parent's central reception.
