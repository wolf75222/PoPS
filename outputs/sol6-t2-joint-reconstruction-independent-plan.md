# T2 joint User reconstruction: independent adversarial plan

Scope read before the author's patch: T2 requires source-authored stencil access and orientation, one joint realization for several occurrences, shared conservative face flux, and no Python callback per cell. The current installed baseline uses scalar `reconstruction.User(sample(offset), formal_order=...)` independently per component; `PreparedPrincipalFlux` packs the complete group, reconstructs one face pair, and publishes one face flux. Existing Primitive coverage checks a joint forward/inverse map but still applies a scalar User policy per component. The new route must retain those cases.

The following five tests are independent oracles, not assertions inferred from the generated implementation. Use the repository's real `validate → resolve → emit → compile → bind → run` fixture, Kokkos field storage, native face flux, and root-only gather. The numerical oracle uses periodic NumPy rolls and computes one canonical positive-axis flux per face. Check both state updates and per-component global sums after one small FixedDt step; a source-only test inspects generated C++ for compiled formulas and absence of host callback invocation.

1. **Joint 2+3, permutation and Primitive conversion.** Build a five-component linear flux with dense 5×5 physical matrices on both axes, split into states of widths 2 and 3. Declare an invertible joint Primitive map in which at least one coordinate and inverse depend on components from both rows. Author a vector User body whose output component 0 reads component 4 at offset +1 and output component 4 reads component 1 at offset −1; include unequal coefficients so transposition is visible. Run both block-registration orders and a nontrivial component permutation. Compare the complete conservative one-step update to an independently evaluated face-pair/Rusanov oracle. Invariant: every symbolic component access resolves against the exact packed group order, and Primitive forward/inverse/admissibility use the same order. Existing scalar User and Primitive paths must still pass.

2. **Common halo across cross-row reads.** In the same two-dimensional group, let a row-0 output read a row-1 component at offset +3 on the x face, while the other row has a shallower own stencil. Repeat with roles reversed and with the y face. Use nonconstant periodic data and compare both rows to the independent oracle. Invariant: all source fields needed by the joint body receive the maximum union stencil envelope; no row-local halo assumption, stale ghost read, or hidden 1D specialization. Declare the exact resulting depth through the native stencil contract rather than a guessed fixed cap.

3. **Live captures and identity.** Use two instances of the same Model, with equal declaration names but different RuntimeParam bindings. The joint body reads two parameters from different row owners, including one coefficient in a cross-component term. Compile once; bind twice with permuted values, then rebind the same artifact. Check all updates change exactly as the oracle predicts and reject a same-name foreign-Model handle at resolve. Invariant: captures are inferred from the expression, qualified by exact owner/instance and read at bind/run; no baked default, row-0 alias, or shared mutable policy table.

4. **Axis and orientation.** Use asymmetric stencils and speeds of opposite sign on x and y (for example +0.7 and −0.4), plus an off-diagonal flux matrix. Compare positive-axis left/right traces and the one-step divergence against periodic rolls. Reflect offsets at negative orientation and exchange states once; a reflected face must yield the same physical shared flux with the correct normal sign. Invariant: orientation changes the sampler geometry, not merely the sign of the final scalar, and adjacent cells consume the same conservative face flux.

5. **Lazy invalid branch, collective refusal and no Python per cell.** A joint body contains a guarded `sqrt` or division that is invalid only for a localized active cell; a separate run keeps the invalid expression in an inactive `where` branch. The inactive case must match the finite oracle. The active case must reject on one rank before publishing any component, clock, exchange, or history; retry from the unchanged state with admissible data must succeed. Put a counter in the authoring callable and verify it is invoked only during authoring/compilation, not by `pops.run`. Do not treat an arbitrary vector body as automatically TVD or positivity preserving.

For each case, inspect source identity after `Case.freeze` and compare generated native closure arity and parameter slots. Reject tuple lengths other than five, nonintegral/bool stencil offsets, foreign instance captures and a body changed after authoring. These are separate admission checks; they do not replace the five execution discriminants.

No new author code or installed native artifact had been inspected or executed when this plan was written. The checks above are acceptance criteria for the upcoming patch, not green results.
