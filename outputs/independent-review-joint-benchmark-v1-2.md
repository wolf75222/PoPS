# Independent review: joint comparison/resource protocol v1.2

Reviewed isolated commit `b2eff53` against the frozen v1/v1.1 scripts, retained failed receipts, authenticated `3d06cab`/`cf6dace` snapshots, and the actual codegen/runtime interfaces. This is a metadata and source review, **not** a timing or comparative resource measurement.

The v1 failure was `layout_program_paths()` on a `dict` property. The preserved v1.1 baseline compile worker passed that site, then failed before any timing at `_abi_environment(str(artifact.abi_key))`: an artifact key has `headers|JIT compiler|C++ standard|dim`, whereas `_pops.abi_key()` has semicolon-separated native compiler/runtime fields. The two `*.failed.json` receipts each record `phase=compile`, exit code 1. Neither failed campaign reports a valid speed ratio.

v1.2 keeps both complete identities and validates their link. `_native_abi` rejects missing/duplicate/empty fields and requires native Dim=2/MPI; `_artifact_metadata` requires the artifact header, compiler, standard and dimension to match its own properties, exact authenticated SDK header signature, and native C++ standard. Cross-lane `_abi_environment` excludes **only** the intentionally different `headers` field; all other fields, including future ones, must compare. Each lane's runtime receipt must still equal its cold receipt in exact artifact ABI, SDK signature, DSO path/size/SHA, platform, compiler and standard. The original snapshot source-file/native SHA pins and doctor checks remain, with `PYTHONPATH`, `POPS_INCLUDE` and `POPS_NATIVE_VARIANTS_ROOT` removed from isolated workers.

The driver runs two no-JIT metadata workers before either cold compile, and cold caches must remain empty. This preflight checks ABI and property/profile **shape**, not an executed profile. The byte-for-byte private DSO image loaded under a random path is excluded from *external dependency equality* only when its SHA matches an authenticated generated or native DSO. Its actual path and hash remain in `recognized_owned_copies`; unknown or tampered images remain in `images`, which are compared by path and hash across lanes. This exemption does not remove the owned DSO identity or relax numerical equivalence.

The case, initial data, bind/run timing boundaries, 48×48 five-scalar User/Rusanov physics, 12 steps at `1e-4`, tolerances, warmups, five timed samples, ABBA order, timeout budgets, and v1/v1.1 files/receipts remain unchanged. The resource companion pins the exact v1.2 runner SHA-256 `d8d96c302079da07420c9acc7352d6b59db2fc8fca69de025ea10cb906fd0afd`, retains separate profiling samples, and still marks absent native counters unavailable rather than zero.

I independently reran all 17 source tests (`17 passed`), verified that SHA pin and `git diff --check`, and inspected the committed audit/receipt. Both snapshot metadata workers actually imported/rehashed their packages and left cache/codegen empty. A copied baseline v1.1 cache supported real artifact-property/DSO hashing, bind, and a two-step structured profile (`source=snapshot`, enabled, steps 2, kernels 6), without a new DSO compilation. The candidate compiled-artifact/profile path and the complete cold-JIT, 12-step ABBA timing and separate resource campaigns have **not** run. The v1.2 receipts correctly call these operations diagnostics, not measurements.

Verdict: v1.2 is a versioned, fail-closed repair of both premature metadata failures and the private-image comparison artifact. It is ready for root's centrally coordinated measurement; no performance conclusion follows from this review.
