# C38 AMR migration audit (2026-09-29)

The contract is `PoPS_Codex_handoff_0.4.0/reference/PoPS_API_v0.4.0/document/03_protocols.tex:121`: quiescent attempts/resources, a disposition for every state/history, one complete candidate, and an atomic topology epoch change. The existing native code already snapshots the accepted engine/carrier/Program before ordinary regrid (`AmrSystem::execute_transaction`), drains prepared resource work, verifies complete level-qualified history descriptors, prepares each history transfer before topology publication, and restores the accepted snapshot on an ordinary failure. Restart additionally checks that every restored numeric slot and its provenance match the authenticated accepted image before commit. Python `RegridTransactionGate` checks a typed due event/schedule/point and excludes rejected attempts; it is a source-level gate, not the native owner of the hierarchy swap.

Two defects were found in the native restart seam. `prepare_history_hierarchy_images` copied a ring with `store_pending=true`, although that flag means slot zero has not yet been logically accepted by rotation. `begin_restart_regrid_history_sequence` retained its frozen image after restart rollback and finalization, so a retry at the same numeric epoch could find the old image still active. The new native test uses a real `AmrSystem` and `AmrProgramContext` ring to attempt a pending-store capture, then abort and finalize restarts and retry the capture. It checks that topology epoch and accepted history values survive the rejection and rollback.

Independent review exposed a second quiescence window: after the public sequence begins, `store_history` followed by `rotate_histories` could replace an accepted ring while the regrid still consumed the older frozen image. The facade now exposes only whether the frozen image authority is active. The Program context collectively refuses authoring stores and rotations while it is active; facade checkpoint/history restoration is also refused before mutation. Internal remap publication remains available to the multi-parent callback. A separate native test holds a real frozen image, attempts all three mutations, checks the accepted ring is unchanged, then verifies authoring resumes after rollback. Both new tests are in the two-rank CTest filters.

The ordinary scheduled multi-parent regrid captures history once before replacing any parent (`complete_program_step_`). A closer inspection of the authenticated Program callback found that `AmrProgramContext::restart_regrid_` also calls `begin_restart_regrid_history_sequence` before its parent loop and `end_restart_regrid_history_sequence` afterward. My first source-only hypothesis that restart lacked a shared descendant image was therefore wrong; it was based on searching only `amr_system.cpp`. The new artifact-backed test exercises three actual levels through `regrid_on_restart`, demands both parent transitions change topology, and compares retained level-two history slots over the original covered cells. Its native result is still pending. The quiescence fix applies to ordinary, bootstrap, and restart history migration. This changes no equations, history calendar, or accepted checkpoint payload.
