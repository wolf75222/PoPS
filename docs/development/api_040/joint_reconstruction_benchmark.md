# Joint reconstruction: bounded 3d06cab → T2 performance comparison

This protocol is fixed **before** collecting timings. Its A/B question is whether T2 changes the cost of an **unchanged scalar User reconstruction**. The retained `3d06cabee9db4a31c4d07fa4e00dc5a40d164155` package cannot author joint vector User, so a baseline scalar run must never be compared to a physically different cross-component reconstruction. A later candidate-only joint run can characterize that new feature, but needs a separate mathematically equivalent scalar formulation and a passed face/state oracle before any relative performance statement.

Use [`joint_reconstruction_benchmark.py`](joint_reconstruction_benchmark.py) on macOS with two complete installed-package snapshots, each containing `pops/`, `identity.json` and `source-files.json`. The runner refuses other hosts because this retained native artifact and its loaded-library check are Darwin-specific. The baseline is the retained workspace snapshot `outputs/artifacts/3d06cab`, whose identity records native SHA-256 `4574ed6096650aa708ad040fd6ee056414a3cfa1735a0440bd74220170265beb`, clean source diff, 1,079 checked source/header files, and an authenticated Dim=2 MPI-enabled Kokkos build. Its source manifest SHA-256 is pinned in the script. The candidate snapshot must be made **after** root installs T2 and records its exact source/native identity; an uninstalled source checkout is not a candidate. Supply the independently expected candidate commit on the command line. The script rehashes every listed installed source/header plus the extension before each worker, checks the imported package path and native SHA, verifies the installed header signature against the loaded ABI, and requires `doctor()` to pass. Both lanes use the *same* Python executable and runtime dependency prefix, with independent `-I` processes, package roots, JIT caches and generated-code directories. It does not modify either installation.

The shared scenario is a 48×48 periodic Cartesian grid, one five-component state, linear physical flux with velocities `(0.7, −0.4)`, Rusanov flux, and a scalar `User` body `sample(0) + 0.2 × (sample(1) − sample(−1))`. It uses FixedDt `1e−4`, exactly 12 accepted steps, and the same deterministic cell-average initial array. Every timed sample binds a *new* RuntimeInstance from the same compiled artifact and starts at that array. The script refuses a missing step, clock mismatch, nonfinite state, per-component drift of the unweighted periodic-cell sum above `1e−10`, or run-to-run nondeterminism. Uniform cell volumes make this sum proportional to conserved mass. It compares the complete final arrays across releases at `rtol=atol=1e−12` **before** reporting a timing ratio. These are predetermined equivalence/non-regression gates, not claims of accuracy against an analytic PDE solution. Output scheduling and diagnostics are identical and disabled except the run receipt itself.

Cold JIT compilation is measured **once per lane** after checking its `POPS_CACHE_DIR` is empty. This means an empty PoPS artifact cache, **not** a cold OS filesystem cache. Resolve time and `pops.compile` time are separate. Runtime uses ABBA worker order (baseline, candidate, candidate, baseline), each in a fresh isolated Python process: two untimed warmups, then five timed bindings and five timed 12-step runs. The predeclared limits are 600 seconds per cold-compile worker and 180 seconds per runtime worker. Thus **10 timed observations per lane, 20 total** are retained with their worker identity, and the report gives median and median absolute deviation. The ratio is descriptive; these short observations on one host do not establish statistical significance or GPU/MPI scaling. The 12 short steps include Python dispatch and transaction costs, so the wall time is end-to-end public step cost, not isolated face-kernel throughput.

Run a read-only plan first, then execute only after the candidate snapshot exists. The following command is a template; supply exact absolute paths for this workspace, the two snapshot roots and the shared `pops-api040` Python executable:

```bash
env -u PYTHONPATH /absolute/path/to/python -I \
  /absolute/path/to/PoPS-numerical-bodies/docs/development/api_040/joint_reconstruction_benchmark.py \
  --baseline-root /absolute/path/to/outputs/artifacts/3d06cab \
  --candidate-root /absolute/path/to/outputs/artifacts/T2-SHA \
  --expected-candidate-commit FULL_T2_COMMIT_SHA \
  --baseline-python /absolute/path/to/python \
  --candidate-python /absolute/path/to/python \
  --output /absolute/path/to/new-empty-results-directory
```

Review `plan.json`; repeat with `--execute` and the same arguments only in a **different new empty** output directory. The runner refuses to overwrite any nonempty directory and preserves timeout/failure logs. Preserve the worker JSON, logs, `.npy` state, generated `.cpp`, DSOs, and `result.json`. Do not rerun into the same cache or delete an unfavorable result. Record machine load, power/thermal policy, and any concurrent activity outside the script if interpreting small differences.

The script records source/native/ABI/header identities, script hash, raw resolve/compile/bind/step times, generated C++ byte count when the requested dumps exist, unique DSO sizes and hashes, and whole-process peak RSS **after** the measured runs. A missing generated source is marked unavailable rather than a valid zero-byte result. RSS includes interpreter and JIT imports; it is **not** a live-buffer or scratch-only measure. It requires the same public artifact platform facts (production System, CPU/host, float64, MPI-enabled with one rank) and hashes the actual non-system libraries loaded by macOS dyld; worker inventories must match across lanes. The shared Python executable keeps compiler/runtime prefix constant, while generated headers and DSOs intentionally differ. The retained C++ provenance banner supplies redacted compile command, `cflags`, `lflags`, compiler and C++ standard when available; the runner also records `xcrun --show-sdk-version`. If either provenance or SDK version is unavailable, external review of exact build flags/SDK is required before a causal performance claim. The ABI key alone does not prove identical optimization flags. The public `RuntimeInstance` has no symmetric profiling surface for this campaign, so native scratch allocations, peak scratch buffer, temporary live bytes, kernel launches and MPI communications are marked **unavailable**, not zero. One-rank execution cannot support an MPI scaling conclusion. `POPS_PROFILE`/private `_executor.profile` is deliberately excluded to avoid a one-sided instrumentation path. An independent native profiler or a common public counter API could add those columns in a separately versioned protocol; no values are inferred from code size or wall time.

`benchmarks/adc757` informed the installed-artifact preflight, refusal behavior and ABBA ordering. Its prepared local-time/rebalance microbenchmark and GPU+MPI qualification are different calculations and are not reused as measurements here. This comparison concerns only the retained `3d06cab` package versus exact post-T2 source/native artifacts, not the migration's original baseline.
