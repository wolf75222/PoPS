# Fixed core expression translation contract @1

The frontend, compiler and runtime translate a language of typed mathematical
operations to native C++. Physics and numerical methods are compositions written
in the Python library. For a fixed core fingerprint, execution must follow the
authored expressions and only those expressions. An operation's mathematical
definition names no physical model.

Changing an expression must change its executed calculation accordingly.
Renaming a model, method, variable or SSA reference must preserve the calculation
when its typed mathematical meaning is unchanged. No expression identity, model
name, known formula or graph fingerprint selects, replaces or refuses a numerical
recipe. Fingerprints and identifiers authenticate provenance, ownership, caches
and installed plans; they do not select a mathematical implementation by identity.

Type, domain, representation, resource and acceptance obligations remain explicit.
They may reject an invalid operation or an unproved requested guarantee with its
mathematical reason. Missing lowering is unfinished language/backend coverage,
not a permanent restriction inherited from the demonstration runtime. Translation
and acceptance are separate: an unknown method-order or SSP proof cannot silently
replace the method's expressions.

The diffusion-to-Field tranche preserves the existing diffusive realization. Its
issued-value envelope describes an actual native allocation and successful write;
it adds no physical formula. The forthcoming accepted-update SSP certificate must
derive its inequalities from typed dependence and rational coefficients, without
matching a method name or a known tableau. An independent Field effect must not
change an unrelated update's calculation. Feedback remains part of the actual
dependency closure and its requested acceptance proof.

Reception requires a recorded core file set and fingerprint, actual installed
package/native identity, independently authored compositions, and metamorphic
checks: harmless renaming and reference reordering preserve results; parameter,
coefficient or expression changes alter native results according to an independent
oracle. A source match or successful compilation alone does not prove this contract.
These obligations are not yet received for the entire PoPS language.
