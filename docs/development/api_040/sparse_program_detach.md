# Lossless detachment of sparse Program identities

The actual installed SDK 02723ae9 reception advances beyond the local-storage
failure but refuses eight product/H05 cases before artifact publication:
`detach_compiled_program changed Program IR identity`. The product's temporary
authoring placeholders consume SSA ids and are encoded as argument roles rather
than executable nodes. In the public five-unknown witness the visible ids are
0,1,2,3,8,9,10,11. A no-drop rebuild incorrectly renumbers them to 0 through 7.
The preserved red probe records only id, input and commit-reference differences;
no scientific equation changes.

The common rebuild now preserves original ids and its next-id counter when all
flat nodes survive and there is no nonidentity alias. Genuine elimination and
aliasing retain compact renumbering. No detach guard or canonical hash is relaxed.
This repairs the documented lossless-clone contract without a new public method,
wire format or native ABI. A public product/permutation test compares serialized
IR, generated C++, references and registry removal; a genuine dead-node removal
test separately pins the optimizer's compact numbering contract.

The broader optimizer regression also exposes an independent default-RHS emitter
regression: its optional User face inspection dereferences an absent model even
though the existing context-based default emitter accepts `model=None`. The
optional inspection now occurs only when a model exists; actual models still
require their complete ProviderPack authority. Existing FE/RK4 no-op CSE and
optimization tests exercise the repaired default route.

Source tests explicitly authenticate the checkout's `python/pops/__init__.py`.
The first unqualified test invocation instead imported the older installed
package and is retained as a failed diagnostic, not evidence for this fix.
Native reception requires the rebuilt installed package and its own before/after
authentication; source tests alone do not qualify local solves or rollback.
