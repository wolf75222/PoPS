# Mapped publication occurrences

A resolved target component retains one physical provider authority. Multiple consumed evaluations of that same authority at distinct Program points are recorded by conditional `mapped-publication-occurrences@1`. Each occurrence retains its full invocation, physical map, source and target ports, and source and target points in validated Program traversal order. Single-occurrence evidence stays unchanged.

Producer, unknown, observation, selected component, physical map and both ports must remain identical. Two distinct invocations at the same target point are refused; competing physical providers remain refused. Reprojection retains one provider entry, and emission requires the exact occurrence, including invocation and both points. Existing Program validation establishes stage causality; this metadata does not authorize a new execution or weaken runtime freshness.

Source checks only. Historical SDK27 publication evidence is unchanged; new Native qualification requires ROOT rebuild/reception.
